# Languages

Zeitlos can speak languages other than English. The English stays in
the source, as the key and as the fallback; translations live on the
card, in the Languages set; a program that has none, or a card without
the set, is simply English.

| | |
|---|---|
| `system.language` | `en` (default), `de`, `fr`, `es`, `it`, `pt`, `nl`, `pl`, `cs`, `sv`, `ru`, `uk`, `ja`; `xx` to test ([config.md](config.md)) |
| `settings` | Language page: a list of the languages the card has; windows opened from then on have it if the machine was in English, everything after a restart ([settings_app.md](settings_app.md#language)) |
| `welcome` | the first question on a new card, when the card has languages |
| the set | "Languages" (`lang`): `jfont`, its glyphs, the catalogs in `/data/jfont/lang/` |

## In a program

```c
#include "../../common/zi18n.h"

int main(void) {
	z_tr_init(Z_APP_NAME);		// first: reads system.language once
	...
	z_win_create(ZS_("Files"), ...);                    // drawn small
	z_dialog_confirm(&dlg, ZS_("Delete"), msg, ...);
	snprintf(b, sizeof b, ZS_N("%d file", "%d files", n), n);
	widgets[i].label = ZS_DC("button", labels[i]);      // a table: NC_() there
```

| | |
|---|---|
| `Z_(s)` | the translation of the literal `s`, or `s` |
| `ZS_(s)` | the same, but only if it can be drawn in `z_font_5x8` |
| `ZL_(s)` | the same, but only if it is all Latin-9 (wm's captions) |
| `Z_C(c, s)` | `s` in context `c`: one English word that is two in another language |
| `Z_N(a, b, n)`, `ZS_N` | singular or plural, by the language's rule for `n` |
| `Z_D(s)`, `ZS_D`, `ZL_D`, `Z_DC`, `ZS_DC` | a string that is not a literal here: from a table |
| `N_(s)`, `NC_(c, s)` | marks a literal in a table for translation, without translating it |

**Which to use.** Almost everything on the desktop is drawn in the small
font, `z_font_5x8` -- titles, buttons, dialogs, help -- so almost
everything is `ZS_`. Japanese has no glyphs that small, so in Japanese
those stay English, as do the day and month names; text drawn at 6x12
(`term`'s larger font, a document) is translated. Plain `Z_` is for
text a program knows it draws at 6x12 or larger.

**What not to wrap.** Anything another program, a file or the network
reads: protocol words, file headers, config keys, log lines, command
names (`REPL`, `POSIX`). Only wrapped strings are ever translated, so leaving one alone is
always safe.

**Whole sentences.** A translation moves words to where its grammar
wants them, so a sentence with a name or a number in it is one string
with `%s` and `%d` in it, never pieces glued together:

```c
ZS_("Delete the file\n%s?")                 // not "Delete the file " + name + "?"
ZS_N("%d match", "%d matches", n)           // not "match" + (n == 1 ? "" : "es")
```

The translation must keep the same `%` conversions in the same order;
`tools/i18n.py` refuses one that does not (a wrong `%s` crashes).

**Measure, don't count.** A translation is UTF-8 and often longer --
German by a third, some by half. `z_text_cols(s)` is how many columns
`s` takes; `strlen(s)` is how many bytes. Cut text with
`z_utf8_fit_cols()`, never at a byte count, or a character is cut in
half. Buttons clip their labels (`zwidget.c`); a row of fixed-width
buttons gets a context, `NC_("button", ...)`, so its translations are
written to fit (files' are seven characters at most).

**The byte drawing functions draw UTF-8.** `z_fb_draw_text()`, and so
`z_win_draw_text()` and every widget, draw a string that is valid UTF-8
with any character past ASCII as UTF-8 ([text_encoding.md](text_encoding.md)),
so a translation draws right wherever a string is drawn.

## What it costs

- **In English** -- or in a program that never calls `z_tr_init()` --
  each `Z_()` is one call that reads its call site's cache and returns
  the literal. Nothing is read, searched or allocated. A game that
  cannot spare even that does not call `z_tr_init()`.
- **In another language**, each call site looks its string up once (a
  hash and a binary search in the catalog) and keeps the answer.
- **The small build** (`Z_SMALL`, Obst) is English: every macro is the
  plain string, and the lookup is not compiled.
- **Flash**: about 1.8K in each translated program for the lookup and
  for drawing other scripts, plus a few bytes per string. The core apps'
  budgets were rebalanced for term, text, files and welcome
  (`Makefile`, "languages"); core flash has no headroom left.
- **RAM**: nothing in English. In another language, `jfont` holds the
  catalogs (about 27 KB in Russian for the twelve translated programs
  today, 2-5 KB each) and 12 KB of glyphs; with
  Japanese, its 175 KB font too.

## Catalogs and translators

**Everything of a program lives with the program.** Nothing is shared
but the shared library's own strings, so adding a program -- in the
tree, built with zcc, or from someone else -- adds its files and
changes nothing else:

| | in the tree | on the card |
|---|---|---|
| a program | `sw/apps/<app>/po/<app>.pot`, `<lang>.po` | `/data/<app>/lang/<lang>.zlc`, in the app's own set |
| the shared library (`common`) | `sw/common/po/` | `/data/jfont/lang/<lang>.zlc`, in Languages |
| a core app (in flash) | `sw/apps/<app>/po/` | `/data/<app>/lang/`, in Languages (with jfont, which reads it) |

`tools/translations/<lang>.json` keeps the translations as they were
written, for `i18n_fill.py`; the PO files are what counts.

A domain is a program (`files`, `text`, `wm`, ...), for every program
that calls `z_tr_init()`, and `common`, the shared library's strings
(dialogs, the date names). A program looks in its own catalog, then in
`common`'s.

```
tools/i18n.py extract        every po/<app>.pot from the sources; every po/<lang>.po brought up to date
tools/i18n.py check          keys hash apart, formats kept (CI runs it)
tools/i18n.py stats          how much of each language is done
tools/i18n.py build OUTDIR   OUTDIR/<app>/<lang>.zlc, and the test language xx
tools/i18n_fill.py LANG F    fill a language's empty entries from a JSON file
```

PO files are what translation tools read (Poedit, Weblate, Crowdin), so
a translator never needs to see the code. The card is built with fresh
catalogs every time (`release/lib/mkfatimg.py`, `lang_files()`).

**The catalog file** (`ZLC1`, `sw/common/zi18n.h`): one per program and
language (the format allows several domains in one, which the host
tests use); a sorted table of 32-bit hashes of the English (with
the context or the plural folded in) and the UTF-8 translations. A
lookup never compares the English, because `tools/i18n.py` refuses two
keys of a domain (or a domain and `common`) with the same hash. A
catalog older or newer than the programs still works: a string a
program no longer has is never asked for, and one the catalog lacks is
English.

**Plurals** are one of six numbered rules, not a formula: n != 1
(English, German, ...), n > 1 (French), and the three-form rules of
Russian and Ukrainian, Czech and Slovak, and Polish; Japanese has one
form.

## jfont: where it all lives at run time

wm starts `jfont` at boot when `system.language` is not English (or
`system.font.japanese` is set). It loads into its arena the language's
catalogs -- `common`'s, and every `/data/<app>/lang/<lang>.zlc` it finds
with one listing of `/data` and one question per folder -- the glyphs the hardware fonts lack (`script5x8.zfn`,
`script6x12.zfn`: Latin Extended-A, Greek, Cyrillic, typographic
punctuation; `tools/gen_script_fonts.py`, from the same public-domain
misc-fixed fonts), and for Japanese the 12x12 font, then writes a
directory (`sw/common/zlang.h`) that every program finds with no message
and reads straight from: a program takes the catalog that holds its own
domain, and `common`'s. It runs until the machine stops: programs keep
pointers into it, which is why the language is chosen at boot -- and
why a program installed since boot is English until the next one. The
directory has room for 48 entries: the fonts and about 45 programs'
catalogs.

**Scripts.** The hardware fonts draw ASCII and Latin-9 (German, French,
Spanish, Italian, Portuguese, Dutch, Swedish, ...). Anything else comes
from jfont's glyphs, drawn in software (`zgfx.c`, `draw_script()`):
Polish, Czech and the rest of Latin Extended-A, Greek, Cyrillic at
5x8 and 6x12; Japanese at 6x12 only.

## The test language

`xx` lengthens every string by about 40% and accents its letters,
inside brackets: `[Délété thé fóldér ~~~~~~~]`. It is drawn in Latin-9,
so it needs no fonts. On a screen in `xx`, a plain English string is
one that is not wrapped, and a cut bracket is a layout that counts
instead of measuring. `make -C sim/sys test-lang ZSYS_CARD=...` boots
in `xx` and in Russian and checks that files asks its question in each.

## Right to left, and shaped scripts

Arabic, Hebrew and the Indic scripts need text reordered and letters
joined. Not yet. When they come, it needs no change to the interfaces
or the programs: the catalog can carry translations already reordered
and shaped (the presentation forms), built by `tools/i18n.py`, and
drawn left to right by every program built today; text a person types
needs the drawing and editing code to learn bidi, which is a library
change. A font for those scripts is another kind of entry in jfont's
directory, which programs that do not know it skip.

## Speech

The voice speaks the windows' language, for eleven of the twelve (not
Japanese), with the formant voice and rules for each language that are
data on the card ([tts.md](tts.md#other-languages)). So what an app
speaks is translated like what it shows:

```c
z_speak(Z_("End of document"), Z_TTS_F_INTERRUPT);    // not z_speak_static()
```

`z_speak()`, which copies, never `z_speak_static()`: a translation lives
in jfont's memory, not the app's. Spoken phrases have no Japanese
translations on purpose, so in Japanese they stay English for the
English voice -- as most of what is on screen does there, in the small
font.

## Where the programs are

Translated, in all twelve languages: `wm`, the shared dialogs and date
names (`common`), and the dock's `term`, `files`, `text`, `read`,
`sheet`, `draw`, `ask`, `calc`, `cal` and `clock`, and the voice's own
words (`tts`). The language is chosen in `settings` and `welcome`, which
are not yet translated themselves.

Still English: `slide` and `learn` (the next two: about 130 and 150
strings, slide's command language staying English), `settings`,
`welcome`, `keyboard`, the console tools a user runs (`update`,
`backup`), and the documents and courses (`/docs/<lang>/`, the courses'
and ask packs' `<lang>` folders are the plan). Games and developer
tools stay English, as do ask's diagnostics about its packs.

**Menus that choose by letter** (`sheet`'s `/` menu): the first letter
of the translated item chooses it when no other item in that menu
starts with it; any other letter is the English item's, so most keys in
the manual still work (not one that a translated initial took). A menu wider than its window scrolls to keep
the highlighted item in view.

**What stays English inside a translated app**: formula function names
and error values (`SUM`, `#DIV0`), file and command names, and what
the voice says (`draw`'s tool names).
