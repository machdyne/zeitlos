# z25519: X25519 and Ed25519 checks on the montmul block

`sw/common/z25519.c`. Drop-in replacements for Monocypher's
`crypto_x25519()`, `crypto_x25519_public_key()` and
`crypto_ed25519_check()`, which run on montmul's register file
([montmul.md](montmul.md#the-register-file)) when the bitstream has it
and nobody else holds the block, and call Monocypher otherwise. Callers
do not need to know which; the results are the same byte for byte and
verdict for verdict.

```c
#include "z25519.h"
void z_x25519(uint8_t shared[32], const uint8_t scalar[32], const uint8_t point[32]);
void z_x25519_public_key(uint8_t public_key[32], const uint8_t secret_key[32]);
int  z_ed25519_check(const uint8_t sig[64], const uint8_t pk[32], const uint8_t *msg, size_t len);
```

**Used by**: the SSH client (`sw/apps/net/ssh/ssh_proto.c`: the key
exchange and the host key check), the SSH server in netserve
(`ssh_server.c`: the key exchange; `authkeys.c`: users' Ed25519 keys),
and TLS in `web` (`tls.c`: the key share and Ed25519 certificates).
zfed will be the next ([fed.md](fed.md)). Signing stays in Monocypher.

## How fast

**Measured on the board** (`cryptobench`): **X25519 83 ms** against
544 in Monocypher, **an Ed25519 check 133 ms** against 722. (Simulation
had suggested ~50 and ~80: issuing and waiting on commands costs the
CPU more than a single MUL's ratio implied.)

## How

Field elements of 2^255-19 live in the block's sixteen registers in
Montgomery form (R = 2^384 on a 12-limb block). X25519 is RFC 7748's
ladder; the Ed25519 check is `[s]B + [h](-A) + (-R)`, doubled three
times, compared with the identity -- extended coordinates, with the
complete a = -1 formulas, so no input takes a special path. Square
roots and inverses are the standard exponentiation chains.

### The same verdicts as Monocypher

zfed nodes with the block and without it must agree on which
signatures are valid, or the network splits. So `z_ed25519_check()`
follows `crypto_eddsa_check_equation()` exactly:

- A and R decoded **negated**; the top bit is the sign of x; y at or
  above p (non-canonical) accepted and reduced; a y that gives no point
  rejected;
- s must be below L;
- the check is **cofactored**: `[8]([s]B - [h]A - R)` must be the
  identity, so a signature whose R has a small-order component is
  accepted -- as Monocypher does, and unlike a cofactorless check.

### Secrets

X25519 runs on secret scalars (every SSH and TLS handshake). So:

- **every command takes the same time whatever its operands** --
  rtl/montmul.v's SUB was made to always run its add-back pass (adding
  N or zero), and `make -C rtl/tests rf` checks every command's time is
  constant;
- the ladder's only secret-dependent step, the conditional swap, swaps
  **register numbers** without a branch; the commands and the register
  allocation are the same whatever the scalar;
- **before releasing the block, every register and the classic A, B and
  R are overwritten with zeros**: the next owner could otherwise read
  values derived from the scalar.

The block is claimed around each call ([montmul.md](montmul.md#sharing))
and its modulus loaded after the claim; if another process holds it,
Monocypher answers.

## Testing

`make -C sw/common/tests -f Makefile.z25519hw`: `z25519.c` against **the
real `rtl/montmul.v`** under Verilator, **Monocypher the oracle for every
result**:

- X25519: RFC 7748's vectors; random scalars and points; u = 0, 1, p-1,
  p, p+1, 2^256-1 and the top bit set; public keys against
  `crypto_x25519_public_key()` -- every output byte-equal;
- Ed25519: RFC 8032 test 1; random signatures from Monocypher and
  tampered copies; and **285 edge cases** from `gen_ed25519_edge.py`
  (RFC 8032's reference arithmetic, independent of both): the eight
  small-order points, R shifted by each, small-order keys and R with
  s = 0 and 1, non-canonical encodings of A and R, s = L, s >= L,
  random 32-byte A and R -- every verdict equal to Monocypher's;
- the block held by another process (Monocypher answers, their claim
  untouched), and after every call the block released and every
  register and R zeroed.

Checked by breaking things on purpose: leaving out the cofactor, or
the s < L check, is caught -- **only by the edge cases**, which is why
they are there; not wiping the block is caught. (Leaving out the
reduction of non-canonical inputs changes nothing: the block reduces
an operand a little above p correctly on its way into Montgomery form.
The reduction stays, because the block's precondition is operands
below N.) One of the RFC 7748 vectors was first typed from memory,
wrongly; Monocypher disagreed with it as well, which is how it showed.
