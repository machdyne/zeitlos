# ls99 -- virtual Zwölf modules

An LS99 is a Zwölf module that exists only on the bench ([bench.md](bench.md)):
Machdyne BASIC and the Sechs module core, as on an LS10 or LS11, with
its pins, its own I2C bus and its Sechs side all on bench nets and buses.
A program developed on an LS99 runs unchanged on the real module, and
what the real module refuses, the LS99 refuses, with the same message.

```
module   m1  LS10  program=/basic/GROW.BAS
bus      main  m1
load     lamp  "Grow light"  m1.C
```

`/bench/growlight.net` and `/bench/modpanel.net` are on the card, with
their programs in `/basic`.

## Which module

| Netlist | Plays | Programs | Pins |
|---|---|---|---|
| `module NAME LS10` | an LS10 | 1KB | A-D, LED |
| `module NAME LS11` | an LS11 | 4KB | A-G, LED |
| `module NAME LS99` | no machine's limits | 32KB | A-G, LED |

The language is BASIC 1 only (no graphics: that is the BASIC computer's).
One interpreter plays them all, told at start which machine it is
(upstream's `BASIC_PROFILE`), and upstream's test suite compares it with
the real LS10 and LS11 builds output for output: a program past 1KB is
`NO MEMORY` on an LS10 while it is typed, `PIN` is not a word on an LS10,
and `SLEEP 57600` is `TOO BIG` everywhere (numbers are 16-bit: count
hours in a loop, as `/basic/GROW.BAS` does).

`INFO` tells a master the truth: `mod=LS99`, and `profile=LS10` for what
it plays. `mod=LS99` is never a real module.

## Settings

| Setting | |
|---|---|
| `program=PATH` | typed in at start, as at its console, then run |
| `addr=` | its Sechs address, 0x0c if not given (as a new module) |

`bus NAME master=m1 ...` makes a bus the module's own I2C bus, its pins C
and D: `PINS NET, NET, I2C, I2C`, then `I2C` and `I2CR` reach the parts
on it. `bus NAME m1 ...` puts the module's Sechs side on a bus, where a
master finds it: `sechs -b main info 0x0c`.

## What it does as a real module does

Each of these follows upstream's `targets/ls1x/module.c`, the firmware of
the real modules:

- **The console** (the I2C console, through `sechs console`): what is
  typed is echoed and run line by line.
- **CONTROL**: HALT stops a running program, RUN starts it, RESET starts
  the module again (its program typed in and run).
- **STATUS, OK, FAULT** kept up to date, a turn after a change, as on the
  module.
- **The pins**: A and B are the Sechs bus: an output there is `BUS` once a
  master has addressed the module. `UART` is not supported, as on the
  module today.
- **REG 0-15** are the Sechs registers 0x80-0x8F: a program publishes, a
  master reads.
- **Files** are the module's own storage: `/bench/NAME/`. `FORMAT` is not
  supported.

What differs: a pin's level is digital (`ADC` reads 0, 1023, or 512 when
nothing drives it), and nothing is timed below a millisecond.

## Time

bench keeps the virtual clock: 1, 2 and 3 in bench set x1, x60 and x3600
(an hour a second), space pauses. A module's own clock only moves when it
waits: computing takes no time, `WAIT` and `SLEEP` exactly their time,
so a program's schedule is exact at any speed. bench may show a change a
frame late at x3600; the program's own timing never drifts.

## Inside

| File | |
|---|---|
| `ls99.c` | the module: console, CONTROL, STATUS, pins, I2C, time, Sechs transactions -- portable, told about its board through `ls99_board_t` |
| `ls99_app.c` | its board on Zeitlos: bench, through the module messages of `zbench.h` |

bench starts one `ls99` process per module, one at a time (a launch
argument goes to the next process started), and tells each its profile,
address, bus and program. The messages: bench sends the time, the levels
of the module's nets, and transactions for its Sechs side; the module
sends its pin drives, its answers, what it prints, and a new address.
Messages from bench that arrive in the middle of something else (a send
waiting for room, the module's own I2C transaction) are queued and acted
on at the board's turn, so a Sechs transaction never runs inside another.

`make test` in `sw/apps/ls99` runs the module on bench's own core in one
process, with exact time: the grow light over 50 virtual hours (on and
off at exactly the right hours, the override keeping it on), the panel on
a TCA9535 with the master reading REG 0, the Sechs side (`S6`, `INFO`,
HALT, RUN, ADDR), the 1KB limit, and `TOO BIG`.
