
## Receive interrupt

Both MACs now raise **`Z_IRQ_ETH` (8)** when a frame is waiting, and
`net` blocks on it instead of polling.

### What it replaced

`net` woke on a 1-tick timer — roughly **732 times a second** — to
discover, almost every time, that nothing had arrived. It had no choice:
neither MAC had an interrupt connected to anything that could wake a
blocked process, so the timeout was the only thing that got the process
running again.

That cost more than idle time. The scheduler shares the CPU between
*runnable* processes, so a process that wakes constantly takes a full
share out of whatever is in the foreground. A full-screen app measured a
quarter of the machine with three such wakers alongside it.

### One line, two MACs

| board | source |
|---|---|
| RMII (LAN8720A) | `ethmac_rmii.v`'s new `eth_int_o` |
| SPI (ENC28J60) | the `ETH_INT` pin, inverted in `sysctl.v` |

`sysctl.v` merges them, so `net` sees one interrupt regardless of which
ethernet the board has — it already abstracts over the two and should
not have to learn the difference here.

The RMII side cost almost nothing: `rx_ready_sync` already existed and
was already synchronised into the wishbone domain for the STATUS read.
The interrupt is that wire brought out. The ENC28J60's INT pin was
already routed and already readable in `spim.v`'s STATUS bit 2 — as that
file's own comment noted, it simply was not connected to anything that
could wake a blocked process.

### Edge, not level — and the first attempt got this wrong

`Z_IRQ_ETH` is **one pulse per arrival**, generated by an edge detector
in `sysctl.v` from the MAC's level-sensitive "frame waiting" signal.

The first version passed the level straight through. It seemed safer —
no window in which the interrupt is acknowledged but a packet is still
unread — and instead **brought the machine to a crawl**: UART output
visibly printing character by character, the dock drawing its icons one
at a time.

`sysctl.v` already warns about exactly this, twenty lines above, in the
note on interrupt bits 4 and 7: *"a latched level source re-fires the
instant the handler returns and the machine stops making forward
progress."* Bit 8 is latched in `LATCHED_IRQ`, so a level there re-fires
forever.

The UART and the audio FIFO escape it by being non-latched **and** by
having handlers that can clear the source — draining the FIFO lowers the
level. Ethernet has neither property: only `net`, a userspace process,
can consume the frame, and it cannot run while the ISR is re-entering.
Non-latched would have stormed just the same.

The lesson generalises: **a level interrupt is only safe when the
handler itself can clear it.** If clearing requires a userspace process
to be scheduled, it must be an edge.

If a second frame lands before the first is read there is no new rising
edge and no second interrupt. That is fine — `net` drains every pending
frame once it runs, and the timeout below is the backstop.

The ENC28J60's `INT` pin is synchronised before the edge detector. It is
an asynchronous pin from another chip, and an unsynchronised signal
feeding an edge detector produces spurious pulses on metastability —
which for an interrupt means a storm that appears at random.

### The kernel side

No handler and no queue. The frame is in the MAC's RX buffer and the
driver reads it from there; all the interrupt has to do is make sure the
driver gets scheduled to look.

The pid is resolved through `k_pid_find()` — a new IRQ-safe table scan,
separate from the `k_pid_lookup()` syscall, which takes and returns
`z_obj_t` and allocates. Looked up rather than fixed because `net`
registers itself like any other service and a hardwired pid would break
the moment it were restarted.

### The timeout stays

`net` still passes a timeout, now `Z_TICK_HZ / 10` rather than 1 tick.
It is no longer how packets are noticed; it is a backstop for the
periodic work the loop still does — ARP ageing, socket timers, TX
retries — and insurance against a MAC that somehow leaves its RX buffer
occupied without the interrupt following.

Ten wakes a second for housekeeping instead of 732 for nothing.
