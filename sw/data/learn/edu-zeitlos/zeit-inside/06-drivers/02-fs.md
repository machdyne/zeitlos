# The filesystem driver

```lesson
(objective "Say which volumes the fs driver serves, and which copy of a file a program gets when it is both on the card and in flash.")
(minutes 15)
(keywords "volume (of storage)" "flash underlay")
```

You will learn how one program, `fs`, gives every other program its
files.

`fs` runs FatFs, the code that reads and writes FAT, the format of SD
cards and USB sticks. It is the only place FatFs runs. It serves one
tree of names made of several **volumes**:

| Path | Volume |
|---|---|
| / | the SD card |
| /ram and /tmp | the RAM disk, in main memory |
| /usb | a USB stick, through the usb driver |
| /nfs | a folder on another computer, read-only, through net, while one is mounted (new: not yet tried with a real server, as of October 2026) |
| under / | the files in the flash |

```sources
(source "Zeitlos docs: fs_driver.md, What fs serves")
```

```check
(choice
  (ask "A program saves a file in /usb. Which drivers take part?")
  (right "fs, which passes the work to usb")
  (wrong "Only usb"
    "Programs ask fs for every file. fs asks usb to read and write the stick's blocks.")
  (wrong "Only fs"
    "fs keeps the folders and files, but the stick is reached through the usb driver."))
```

## The flash underneath

The core of Zeitlos, its drivers, `wm`, `term` and a few apps, is kept
in the flash, so the machine works with no card at all. `fs` shows those
files **underneath** the card: the **flash underlay**.

- A file on the card hides its copy in flash. A newer version of a
  program can be tried by putting it in the card's `/apps`.
- A file only in flash can be read but not written.
- Deleting the card's copy brings back the flash one.

```sources
(source "Zeitlos docs: fs_driver.md, What fs serves (the flash underlay); tc.md, Getting Back to Safety")
```

```check
(choice
  (ask "/apps/term is both in flash and on the card. Which one starts when you open term?")
  (right "The card's copy")
  (wrong "The flash copy, because the flash is safer"
    "A card file hides its flash copy. That is how a newer program is tried without touching the flash.")
  (wrong "Neither: the clash stops both"
    "There is no clash: the card's copy simply wins."))
```

## The one that must be in flash

Every driver except one can come from the card if a copy is there. `fs`
always comes from flash: nothing can read the card before `fs` is
running. The kernel itself is a client of `fs`, through the same
library as the apps; it asks `fs`, for instance, when it looks for a
program on the card.

The SD card's region, B, is closed to ordinary programs by the MPU. Only
a driver may use it.

```sources
(source "Zeitlos docs: userspace_drivers.md, Growing past the flash region (only fs must stay in flash); fs_driver.md, Who talks to it; mpu.md, The rules (MASK)")
```

```check
(choice
  (ask "Why can fs not be replaced by a newer copy on the card, as usb and net can?")
  (right "Reading the card needs fs, so fs must already be running from flash")
  (wrong "Because fs is part of the kernel"
    "fs is a driver program. It is the order of things that keeps it in flash.")
  (wrong "Because the card is read-only"
    "The card is read and written. The problem is reading it before any filesystem runs."))
```

---

```check
(choice
  (ask "What happens to the files in /ram when the power goes off?")
  (right "They are lost: the RAM disk is main memory")
  (wrong "They are saved to the card"
    "Nothing saves them. The RAM disk is fast because it is only memory, and it is lost at power off.")
  (wrong "They are saved to the flash"
    "The flash holds the system, not the RAM disk. /ram is gone at power off."))
```

So: `fs` serves the card, the RAM disk, USB sticks and the flash's files as one tree, with the card's copy of a file hiding the flash's.
